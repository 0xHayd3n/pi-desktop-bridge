# Architecture

```text
Codex / another MCP client
  │ local stdio MCP: images + typed input tools
Windows/macOS/Linux Python bridge
  │ authenticated, host-key-checked SSH; JSON lines
Pi user-owned Python agent
  │ private UNIX domain socket; RFB
Pi user-owned WayVNC process / grim / wtype
  │ Wayland capture + virtual pointer/keyboard
Existing Raspberry Pi Wayland desktop
```

The local server uses the official Python MCP SDK. In stdio mode, a single persistent OpenSSH process carries requests and responses. Input and the resulting screenshot run under one lock so concurrent tools cannot interleave a keyboard chord or a drag. Failed input is never automatically replayed: a connection can fail after an action was already applied.

Protocol version 4 starts each SSH connection with a lease-free `hello` exchange. It advertises the agent version, source hash and supported methods, including visual stability waits. Incompatible agents are rejected before desktop operations with deployment guidance. `health` checks prerequisites without initializing WayVNC. The source hash is captured when the agent process loads so a running old process does not report newly deployed on-disk code as its own.

Remote errors carry a stable code and an input state. A preflight rejection is distinct from uncertain delivery. The MCP server requires a fresh successful screenshot after uncertainty or an acknowledged action with failed capture. These errors do not trigger a replay. Valid preflight errors preserve a healthy SSH connection; malformed protocol responses invalidate it.

Each tool enters asynchronously and shares a monotonic deadline across queueing, negotiation, writing, reading and post-action capture. Only the serialization lock owner starts a blocking SSH worker. A cancelled or expired waiter cannot deliver input later or stop another caller's active process. Cancellation after work starts retains the lock through completion and bounded cleanup; cancelled input requires a new screenshot even if its background capture succeeded. A cancelled screenshot does not clear an existing observation requirement. All observation, action and release tools use the same serialization lock.

The Pi agent uses Python's standard library, WayVNC, `grim` and `wtype`. It takes an exclusive per-user runtime lease before starting its owned WayVNC process, preventing independent bridge clients from interleaving input. It creates a private directory under the user's runtime directory and communicates using RFB over a UNIX socket. It does not expose an HTTP, WebSocket or VNC network listener. `grim` captures a fresh PNG directly from the compositor on the selected output, avoiding WayVNC's initial placeholder and cached framebuffer. `wtype` sends Unicode text using a virtual Wayland keyboard; text goes through stdin, not shell arguments, and the clipboard is not changed.

Full native screenshots retain grim's PNG encoder. Region and resized screenshots capture the selected full output as P6 PPM into a private anonymous file, verify its original dimensions and exact bounded payload, then sample bounded RGB rows and encode lossless PNG with the standard library. Cropping happens in original output pixels: grim 1.4's `-g` uses compositor layout coordinates and `-o` overrides that region, so combining those flags cannot safely express a local-pixel crop. This approach reduces transferred image size while still capturing the full output. Output identity and geometry are checked before and after capture, with a compositor race still possible between those checks.

Frame metadata separates PNG dimensions from original desktop dimensions and identifies the source rectangle. For an image pixel `i`, source dimension `s` and image dimension `n`, the original pixel is `origin + floor((2*i+1)*s/(2*n))`. The same pixel-center mapping is used for downsampling and optional image-coordinate mouse input. Each successful capture receives a random frame token; only the latest token bound to the current RFB client is accepted. Tokens are consumed when input starts and cleared on close. The MCP server validates metadata before retaining its current view and maps both drag endpoints. Remote token checks reject an old view even when the local transport reconnects. Partial captures never clear an uncertain-input observation requirement.

Visual stability waits capture PPM on the Pi and hash every native RGB pixel in the monitored rectangle. Return-image resizing does not reduce the comparison's resolution. At most two bounded anonymous files retain the latest fully validated sample and the next candidate, so expiration during a later capture can return the prior valid image. A candidate is promoted only after its capture, geometry and payload checks succeed. A normal sampling deadline returns a timed-out result; genuine helper, malformed-output and display-change failures remain errors. The exact retained sample is encoded once at the end. Session setup, bounded helper cleanup, PNG encoding and transfer are outside the sampling duration but remain subject to the local tool deadline. The image still represents a sampled moment, and equality across samples cannot establish application readiness.

Post-action screenshot sizing is configured locally and checked before dispatching input. The resize parameter is sent only to the subsequent screenshot RPC, and the returned full-source bounds and dimensions must match it. Status and health add local recovery flags under the same serialization lock; neither visual waits nor status queries clear an uncertain-input guard.

The zero-byte lease file persists in the runtime directory to avoid races caused by replacing its inode. The kernel releases the file lock when the owning agent closes or exits. It is not a daemon or a permanent background service.

The explicit disconnect tool closes the bridge's SSH agent and owned desktop processes while leaving the MCP server available for lazy reconnection. Invalid first actions release any session acquired for bounds checking. Input preflight queries the private WayVNC control socket to check output identity and dimensions before events are sent. Scroll targets use original screenshot coordinates; an unknown initial pointer position is never substituted with `(0, 0)`.

An optional local lifespan task releases an idle desktop session after 300 seconds by default. It uses the same action lock as tools, checks activity again after acquiring that lock, and awaits its executor disconnect through cancellation. It cannot close a session while another worker owns it. Completed desktop operations renew the interval; diagnostics and rejected/queued-cancelled calls do not. Potentially held sessions after uncertain outcomes also age out. A background release invalidates local views and preserves the observation guard, with one quiet cleanup attempt per activity interval. Normal server shutdown joins the timer's cleanup before final disconnect. The timer runs in the MCP process; the Pi agent stays single-threaded.

Each SSH startup uses a fixed standard-library bootstrap that reads at most one MiB of agent source into a snapshot, compiles and executes those exact bytes, then binds their SHA-256 before calling the agent's entry point. This avoids an atomic deployment replacement causing old executable code to advertise a new file's hash. The client pins its expected packaged-agent hash on import. A compatible handshake with a different hash permits diagnostics and cleanup but blocks desktop RPCs before their pipe write. The hash is a source-consistency check, not an authenticated attestation from the remote machine; OpenSSH's existing trust remains required.

The desktop must already be running under the SSH user. This controls the Pi's graphical session; it does not capture or control another computer connected to the Pi's HDMI port. SSH keys remain in the client's normal store. Deploying the agent needs no root access and does not alter system services or firewall rules.

## Local connection and desktop viewer

The `ui` command serves packaged HTML, CSS, and JavaScript on a pre-bound IPv4 loopback socket. Its private launch link carries a random capability in the URL fragment, which the browser removes after reading it. The API uses a Bearer header; it rejects unexpected raw Host and Origin headers, requires a matching Origin on POST requests, and provides no CORS allowance. Responses disable caching and framing, and the page uses a restrictive content security policy without external assets. The capability protects local access; it is not a remote network service or a replacement for SSH authentication.

Connection details go directly from the page to this local API, rather than through model-facing MCP tools. Saved aliases use the existing strict OpenSSH path. Direct username/password or local-key login uses Paramiko in the local process. An unknown key requires an explicit matching fingerprint before authentication; a changed key already in OpenSSH's known-hosts store is rejected. New confirmations are in memory for the connection and are not written to SSH configuration. Authentication errors are reduced to safe codes and messages. Passwords are neither persisted nor sent in subprocess arguments or environment values; closing the connection releases their references, without claiming secure erasure of Python memory.

The GUI transport authenticates and performs the same source-checked, lease-free agent negotiation as stdio mode. Optional deployment sends only the packaged agent through the fixed deployment routine and verifies its hash. The viewer then opens a separate fixed `stream_main` entry through that authenticated connection, or its strict OpenSSH alias. The executed agent source, protocol and bounded startup metadata are checked before sending START and acquiring the Pi desktop lease.

The stream agent starts an owned WayVNC process with a private UNIX socket. Its 1000 fps capture ceiling lets WayVNC 0.9.1 request the next changed frame promptly: that version's ext-image capture schedules from completion and subtracts 4 ms from the interval, so a 60 fps cap can miss alternate display refreshes. This is a capture ceiling, not a displayed-rate promise; capture remains serialized and actual cadence follows the compositor, encoding and client backpressure. The agent relays raw RFB between that socket and SSH stdio without invoking grim or inserting JSON after startup. An authenticated HTTP response carries binary RFB to the bundled, unmodified noVNC 1.7.0 client. A small channel adapter sends ordered bounded input requests and acknowledges them only after SSH delivery. The viewer omits the optional Fence encoding, avoiding a separate HTTP input POST for each Fence reply while retaining ContinuousUpdates. noVNC sends pointer, keyboard and wheel events directly; the viewer does not capture an image before or after input. Actual update rate is content and route dependent. Vendored licenses and provenance accompany the client; no CDN is needed.

The raw viewer omits WayVNC's `-r` flag so cursor pixels are excluded from desktop frames. WayVNC separately captures cursor shapes and NeatVNC distributes them to Cursor-capable clients; the retained geometry probe does not prevent the browser receiving them. noVNC draws the received cursor locally, with `showDotCursor` covering startup, transparent shapes, and compositors without cursor-shape capture. The dot remains visible when a remote application requests an invisible cursor. Pointer movement therefore avoids the video path, while hover effects, clicks, typing and cursor-shape changes still depend on the Pi. MCP screenshot sessions keep `-r` and include the remote cursor as before.

After a direct Paramiko login authenticates, the controller enables `TCP_NODELAY` on native IPv4/IPv6 SSH sockets to avoid delaying small input packets. Unsupported socket wrappers or socket-option failures leave the connection usable. The saved-alias path uses OpenSSH, which already enables this option; this change does not claim a speed gain for that path.

Opening a stream requires exact Host and Origin headers and a single-use 15-second ticket bound to the current connection generation. The HTTP endpoint accepts the ticket in an authenticated JSON body, returning a fresh private channel identity in a response header. Input requests require that identity in a header and the launch Bearer capability. A separate WebSocket endpoint carries tickets through subprotocol negotiation. Neither transport puts stream secrets in URL query strings or logs. Incorrect claims do not consume the valid ticket or renew inactivity. The server accepts at most 64 KiB of input per request, bounds body reading, limits concurrent readers and queued data, and closes stalled sends. Cancellation drops unsent input; uncertain active delivery closes the session without replay. Output and input tasks are joined before ownership is released, including disconnect during startup or before the response iterator begins. SSH diagnostics are drained without logging their contents. Setup, writes, rekey waits and teardown have finite bounds; a blocked pipe owner is terminated, with a kill fallback. Profile replacement and disconnect join owned work before releasing the authenticated connection.

The controller reserves one stream per connection and rejects legacy frame/action requests while streaming. The separate stdio MCP API retains its screenshot-based observation and uncertainty guards. The browser stream does not use those image tokens; input travels in order on its own leased RFB session and is never automatically replayed. A visible-tab heartbeat renews a 30-second local inactivity policy; raw RFB traffic does not. Closing, hiding or abandoning the tab eventually releases the session and its lease. F6 leaves keyboard focus, and clipboard access occurs only after an explicit paste gesture. Paste preflight rejects unsupported non-ASCII text before sending any part; delayed clipboard reads are invalidated by focus loss, later input or disconnect. Held pointer buttons and keys are released before suspending input.

Screenshots are returned to the MCP client and may be processed by its AI service. The server does not save a screenshot history. Explicit screenshot exports and the opt-in live verification script save only where requested. Captures and verification output under `_local/` are excluded from Git; exports saved elsewhere can be tracked and must be kept out of commits when private.

The remote protocol contains only desktop status, capture and input methods. It is not a general shell-execution API. Screen content remains untrusted data; the assistant should follow the user's task rather than instructions displayed inside a screenshot.
